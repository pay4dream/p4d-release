1.1.2 更新

  • KV 创作成为第五工作区：与图片生成、3D 分镜、视频生成、剪辑并列。主体、场景、构图与风格参考集中在同一份 KV 草稿里，换一个参考或要求就能继续做变体。
  • 参考选择生成静态 KV：按参考槽位组织素材，生成完整静态主视觉。生成前确认标题、模型、尺寸、引用数量与费用；确认只授权当前一次提交。
  • 3D 构图往返：从 KV 草稿进入 3D 构图，调整角色、场景与机位，再把捕获结果写回同一草稿。已选的角色、场景与风格会保留，不会用推测机位替代真实构图。
  • 一键动态 KV：选中静态 KV 后直接作为图生视频首帧，不必另建镜头或切换工作区。可选用人物微动、环境氛围或缓慢运镜预设；确认费用后才生成，结果回到同一张 KV 卡，原静态图保留。
  • 显式操作、失败不自动重投：静态与动态 KV 每次生成都需要一次明确确认。失败或受理结果未知时不会自动重复提交，避免在未核对任务记录前产生重复费用。
  • 随包提供本机会话工具：安装包内含 p4d-cli、其别名 p4d 与桌面 Agent API 使用说明，方便 Agent 和脚本通过正在运行的桌面应用完成本机会话。

本机会话与 Agent API

p4d-cli 与 p4d 是同一个随包客户端，通过仅限本机、需要认证的回环会话连接正在运行的 Pay4Dream。它们复用桌面应用已有的数据、权限、供应商与渲染能力，不另开数据库，也不直接调用模型服务。

  • 用途：Agent 或脚本可以发现本机会话、查看命令目录、读取当前项目与任务，并请求执行允许的操作；KV 草稿、结果展示、费用确认和可视化仍回到 Pay4Dream 桌面界面。
  • 版本边界：客户端与应用必须版本完全一致。未发现运行中的会话或版本不匹配时，操作会在提交前停止。
  • 收费与敏感操作：付费、破坏性、敏感操作既要有命令行中的显式许可，也仍受应用内既有确认约束。KV 的生成请求只能打开费用确认，不能由命令行直接扣费；反馈提交也只在桌面界面由你确认。
  • 超时与未知结果：请求可能已送达时不会自动重试。先用请求编号查询状态，或到任务历史与资产库核对，再决定是否显式重开。
  • 安全边界：会话令牌不会打印在命令输出或错误信息中；不要把模型服务密钥直接写进命令行、共享脚本或反馈内容。需要传递敏感输入时，使用本机文件的受限权限或标准输入。

详细命令与恢复流程见随包 P4D_CLI.md，也可以在桌面应用运行时执行 p4d-cli guide。
